**Doc spike:** `projects/qa-job-hunter/docs/spike-pipeline-gmail-llm-match.md`

## Problema
Hoy hay **dos motores de match** sin unificar:

| Camino | Cuándo | Motor | IA |
|--------|--------|-------|-----|
| **Campaña Gmail** (canónico) | `npm run campaign` → applied-list `run-pipeline` | `scripts/match-jobs.ts` — regex / cobertura skills | **No** |
| **Hunter scrape+analyze** (opt-in) | `2-scrape-jobs` → `3-analyze-match` | `llm-client.ts` — Ollama / Claude / regex | **Sí** |

Ollama (`LLM_PROVIDER=ollama`, `qwen2.5:1.5b`) **no participa** en el pipeline Gmail que alimenta Excel, Mongo y dashboard.

**Síntomas dashboard (post #313):**
- Summaries regex (*"Encaje sólido (100%) — CV automation"*)
- Muchos 100% (poco granular)
- `gaps` / `cvSuggestions` vacíos cuando regex cubre todo
- `applications.analysis` a veces incompleto (fix parcial en `feature/e2e-dashboard-pipeline`)

## Objetivo del spike (éxito)
1. **Decisión de arquitectura** documentada (opción A / B / C del spike doc).
2. **POC mínimo** 5–10 jobs: Ollama vs regex → `matched.json` → dual-write `applications.analysis` → dashboard detalle.
3. Tabla comparativa (match%, skills, gaps, summary, latencia).
4. Veredicto **GO A / GO C / stay regex** + stories de implementación si GO.
